## 5001 - Communication Mode

| Data Value | Lens Status Code | Function |
| --- | --- | --- |
| 0x01 | 0x2001 | Sent at startup |
|     |     |     |

Body sends this after doing all the initial querying of the lens at startup. Immediately after this the lens starts emitting status messages.

It also gets emitted if the camera body has gone to sleep and the shutter is pressed to wake it up (needs to be full sleep, not just screen blanking). Probably because it has turned the lens off and now needs it on again.

This feels like it is enabling the status and event messages.

## 5002 - Electric MF Permission

| Data Value | Lens Status Code | Function |
| --- | --- | --- |
| 0x00 | 0x2001 | Allow MF/iFN ring to control focus.  <br><br/>   <br><br/>Sent when lens gets locked.  <br><br/>Sent when lens AF/MF switch changed to MF.  <br><br/>Sent at startup if AF/MF switch in MF mode.  <br><br/>Sent in AF mode if DMF is enabled and shutter half-pressed. |
| 0x01 | 0x2001 | Don't allow MF/iFN ring to control focus.  <br><br/>   <br><br/>Sent when lens gets unlocked  <br><br/>Sent when lens AF/MF switch changed to AF.  <br><br/>Sent in AF mode if DMF enabled and shutter released. |

I think this controls whether the MF/iFN ring can control the focus if it is in MF mode. Sometimes even in MF mode (e.g. lens locked) it shouldn't change focus with the ring.

If DMF is enabled in the camera settings it re-enables MF control when the shutter is half-pressed.

Compare with the 0x500E which tells the lens to use the ring for MF (if enabled with this 5002 code).

## 500D - Operating Method Permission

| Data Value | Lens Status Code | Function |
| --- | --- | --- |
| 0x10 | 0x2001 | Enable iFN button events.  <br><br/>Sent when shutter button released from half-press or after capture finished if full-press.  <br><br/>Sent at power-on. |
| 0x11 | 0x2001 | Disable iFN button events.  <br><br/>Sent when shutter button half-pressed.  <br><br/>Sent at power-off. |
|     |     |     |

There may be something specific here for DMF lenses? need to check.

A lens in MF still emits the 0x7001 status when the ring is twiddled, so looks like this only affects the iFN Button.

On lenses with the extended 0x500D states in op1006, can't find anything that causes a set of 2x or 4x states. Always just these 0x10/0x11. Interestingly on the NX1 it doesn't send the 0x11 when shutter half-pressed, just the 0x10 when released - and then not if a full-press happened.

On the NX1 when iFN is pressed it sends a 0x11 followed by an 0x10.

In the logs on the NX1 see `CCapCmdIf::SetLensIFNPermission(1)` which I think corresponds with this. It has values 1,2,3,4st but only see the 0x10/11 in the capture.
