This operation gets the 'specific data' constants from the lens.

A lot of the responses come in multiples of 1 (for primes) and 18 (for zooms) with exception of 10 for the 60mm prime

I suspect this is because a lot of parameters vary with the focal length. The focal length can be varied mechanically in infinitesimal steps, so the camera just divides the full range into a number of steps, and provides constants for each of the steps. I guess the camera could interpolate for in-between values, not sure if it does. Investigation showed that this number is the number of 'zoom points', and is a way for the lens to provide different information for different levels of zoom (near to far).

The 60mm is an odd one out, it may be using this mechanism to provide some compensation for something other than focal length. It has a range of values in 600C for 60-40mm (the only lens with values in decreasing order), but the 600D always reports as 60mm.

### Investigation

- The camera internally uses a single number to describe where the focus mechanism is. This number is related to the mechanics of the lens and how it is actuated, and is not a 'distance' that the camera is focused at. Could consider it steps of the stepping motor or equivalent smallest increment of the focus mechanism.
- Cameras with 0x6022 and 0x602D are able to convert the mechanical position into a distance.
- The mechanical position appears to be a single integer.
- For zoom lenses there are different parameters for each of the zoom points. The 60mm lens does something special here, see the notes on zoom.
- On zoom lenses the amount of focusing available increases over the zoom range (sometimes not by much), and is bigger for longer focal lengths. 0x6007.

&nbsp;

The `st cap lens` command also reveals some internal names.

- when doing 'near' 'far' focus moves, we see wMin, wMax, and m_stPropertyInfo.wafovermin, m_stPropertyInfo.wafovermax.
    - The wmin and wmax are just the INF and INF+range.
    - The overmin and overmax vary across the zoom point.
        - They vary across instances of the same lens by the amount the AFINF value changes.
        - The overmax-overmin is the same across instances of lens.
        - overmax &lt;-&gt; overmin symmetrical around the AFINF &lt;-&gt; AFINF+Range
        - the amount outside min/max varies across zoom point, but constant across lens instances. different across different lens types
- \`backlash' just gives the backlash value - although on at least one lens with 0 in 600A, it reports 10. The S lenses have values less than 10 in 600A. Perhaps if 600A is 0, it really uses 10.

- 'focuspos' just gives the INF and INF+range values, as well as the current value.

### Understanding

Internally the camera treats the focus position as a unit-less number between the minimum and maximum values reported by the lens for each zoom point.

For each zoom point the lens specifies a number for infinity focus, and an amount of steps to get to the nearest focus position. There is also a mechanical limit.

### Investigation

- The 'st cap lens'
    - 'getrange' returns a min and max for the iris, which appears to be the number of elements in 0x600E.
    - 'lensinfo' gives a lensproperty.iris_point. So i suspect it's using the indexes into the tables internally rather than a specific f/number.
- The camera use an 'iris_point' internally, rather than the f-stop value. These are indexes into the 600E array.
- The values across instances of the same type of lens are different in 0x600E.
- As the zoom point changes, the minimum iris_point can change, and this is given by the 600F table.
- The values in the 0x600F table don't always occur in the 0x600E table.
- Nominal_f_number, the first element is always very close to the first element of 0x600F, and the last element is (for the zoom lenses) close to the last element of 600F. The middle number is almost always 144.
- Across lenses, the values in 0x600F match f-numbers across lenses. E.g. A f3.5 on the 18-55 gets the same value as a f3.5 on the 20-50mm or 10mm. So there isn't anything different in the maths across lenses.

Looking at the 18-55mm lens on the wide setting. The \`iris_point' for each f-stop on the camera and the index into the 600E table is below. Need a way to relate the table value to the f-stop. As this is something all lenses do, the data relating a 600E value to an f-stop must either be intrinsic to the representation, or calibrated with constants somewhere.

It's not a simple multiple, because 59/3.5 != 142/22 by a large amount.

### Understanding

Internally the camera uses 16th stops. https://en.wikipedia.org/wiki/F-number

It either calculates or has a table where the values are f = sqrt(2)^(n/16) where f is the f-stop and n is an index from 0-255 (allowing f-stops in the range 1.0-250.51). E.g. sqrt(2)^(59/16) = 3.5, or for 142 we get 21.7. This means the camera doesn't support f-stops below 1.

The aperture mechanism control is simply a single number 0..m depending on the lens. The camera calls this the aperture_point. A value of 0 gives the smallest f-stop (widest aperture, least movement of mechanism), and a value of m gives the largest f-stop (smallest aperture, most movement of mechanism). The performance of the aperture mechanism is calibrated for each lens, resulting in a table that maps each aperture_point to a number n which can be converted to a f-stop using the previous formula. This data is stored in 0x600E, and is all the f-stops that the lens can produce.

Depending on the construction of the lens the minimum f-stop available at any zoom_point can change. 0x600F lists the minimum aperture number n which can be converted to an f-stop using the previous formula.

The lenses datasheet specifies the aperture as the range of minimum f-stops across the range of zoom (e.g. F3.5-5.6), and the maximum f-stop. 0x6010 Stores this information. First element is the minimum f-stop at minimum zoom, second number is the maximum f-stop, and third number (present when a zoom lens) is the minimum f-stop at the maximum zoom.

The 45mm 3D lens does funny stuff with extra lenses internally, and table 601F must describe be this. The 60mm also seems to be a bit special with the 'FI' versions of some registers which aren't very different to the normal ones.

All lenses support this.

In each set of 10, it starts high and goes lower.
