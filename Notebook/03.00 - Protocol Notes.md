When the camera starts communication with a lens it sends a sequence '0x03,10,01'  and the lens responds with a table of information about what it supports.

For some of the codes in the information table (50xx and 60xx) the camera then queries additional information (every startup for 50xx codes, and only on first observation of the lens for 60xx codes).

# Structure

After the framing covered in [01.02 - Low Level Protocol](projects/samsung%20nx%20protocol/01.02%20-%20Low%20Level%20Protocol.md) (basically just a packet length of either 1 or 5 bytes), the messages are formatted as follows:

## Body to Lens

| Size (bytes) | Part | Note |
| --- | --- | --- |
| 1 or 5 | Packet length |     |
| 2   | Operation | An operation code |
| 3..N-1 | Payload | Opcode specific payload |

&nbsp;

## Lens to Body

| Size (bytes) | Part | Note |
| --- | --- | --- |
| 1 or 5 | Packet length |     |
| 2   | Status | A Response or Status code |
| 3..N-1 | Payload | Response/Status specific payload. |

# Sequences

As described in the Low Level Protocol section, there are three basic sequences.

1.  Camera sends packet to lens; lens sends packet to camera.
2.  Camera polls lens; lens sends packet to camera.
3.  Lens sends status/event to camera.

Type 1 and 2 are initiated by the camera, either by sending a packet to the lens or by polling it. Type 3 is initiated by the lens asserting LDREADY without a preceding packet or poll from the camera.

Code groups 0x1xxx, 0x2xxx, 0x4xxx, 0x5xxx, 0x7xxx are observed as bytes 1-2 of the packets. The table below shows where the code groups are seen and whether they are in data from the camera to the lens or vise-versa.

| Code Group | Direction | Sequence Type 1 | Sequence Type 2 | Sequence Type 3 |
| --- | --- | --- | --- | --- |
| 0x1xxx | Camera->Lens | Y   |     |     |
| 0x2xxx | Lens->Camera | Y   | Y   | Y   |
| 0x4xxx | Lens->Camera |     | Y   | Y   |
| 0x5xxx | Lens->Camera |     |     | Y   |
| 0x7xxx | Lens->Camera |     | Y   | Y   |

# Operation, Register, and Status Codes

The features of the lens and the operations that can be performed on them are given 16-bit codes, grouped by the upper 4-bits, or maybe 8-bits with a subdivision.

On the linux based cameras it's possible to get a telnet console where the command 'st cap lens' shows the lens capabilities. From the output we get some descriptions, and can confirm by looking at the camera logs and comparing with what features we know are common across lenses.

&nbsp;

## 0x1xxx Codes: Operation Support

No labels are given for these, but the values match bytes 1-2 of the packets the camera sends to the lens. Feels like it makes sense, that these are the 'operation' to perform. There can be parameters after the operation code.

There are gaps in the codes. Not sure if they don't exist, or are intrinsic so don't need to be listed (although would have thought 0x1001 would be intrinsic).

Some of the codes are present only on lenses with particular features, so can guess what they might be.

The 'st cap lens' lists the properties, but doesn't say which enum is which constant. Started by taking them in the order listed in the output, but it was obviously not correct for most.

By observing the data and logs on different lenses can get a pretty good idea about what property codes correspond with each label. E.g. OIS is 0x500A because when we change the OIS setting on the camera an operation is done on 500A; and its only present on lenses with OIS.

## 0x6xxx Codes: Specific Data Support

Although these are listed in the information table, the camera didn't initially appear to do anything with them.

It appears this is static information contained in the lens, so to save time at startup the camera caches this information. Can force the camera to request this information by doing a 'reset' and then power cycling the camera.

NB: While the NX1 console had called this SPECIFIC data in the enums, it may actually be SPECIFICATION data.

## 0x7xxx Codes: Status Support

No labels are given for these, but looking at the communication logs and features of lenses that support the codes it's possible to identify the related functions.

| Code | Note |
| --- | --- |
| 0x7001 | Related to Focus |
| 0x7002 | Related to Aperture |
| 0x7003 | Only lenses with a zoom 'lock' have this |
| 0x7004 | Only lenses with OIS have this |
| 0x7005 | Only lenses with 3D have this |
