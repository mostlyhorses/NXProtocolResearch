# Support

All lenses

# Camera Request

&nbsp;

| Byte | Example | Note |
| --- | --- | --- |
| 0   | 07  | Length |
| 1-2 | 0x11,01 | This operation |
| 3   | 0x30 / 0x40 / 0x50 / 0x60 / 0x80 | Type |
| 4   | 0x00 / ... / 0xFF | Speed |
| 5-6 | 0x00,5C | Position |

Some logs call bytes 5-6 'amount', but I think its actually an absolute position not an increment.

&nbsp;

# Lens Response

| Byte | Example | Note |
| --- | --- | --- |
| 0   | 04  | Length |
| 1-2 | 20,01 | Status |
| 3   | 0x00 | Movement status. 0: still, 1: moving |

&nbsp;

The movement status in the response appears to be 0 if the mechanism was still before receiving the command, and 1 if it was still moving.

# Notes

&nbsp;

The type codes seem to be used at different stages of focusing. Perhaps it's not so much an instruction to the lens, as the camera reporting its certainty, e.g. at the beginning the camera doesn't know if it needs to go in or out so issues an 0x30, but once it can see that things are getting better or worse it issues an 0x40, and then when it realises it's gone past the optimal point it issues an 0x50 with the final value it wants. 0x60 is used when the camera wants the lens to stop now. 0x80 is used when about to power off.

| Type Code | Note |
| --- | --- |
| 0x30 | Seems to be issued with Speed 0xFF. Often the first op 1101 request, but not always. Maybe its the camera saying 'I really don't know' where to go. |
| 0x40 | This looks to be the most common type. As the focus is hunting it will send out different speeds with the same position, or different positions if it wants to try going back the other way. Could be camera saying 'I'm pretty sure its this way'. |
| 0x50 | When camera realises it's gone past the optimal point, it issues this type with the final position it wants. Could be camera saying 'This is it'. |
| 0x60 | Seems to be used with a speed of 0 and a position that is often around 0x89. Suspect this is a way to tell the focus to 'stop moving now'. |
| 0x80 | Issued when turning off. speed 0xFF position 0. |

&nbsp;

In the NX1 terminal you can use the `st ap iq af mv` command to issue movement commands. Interestingly it takes a delta as the argument rather than the absolute position that is sent in the message, but prints the current and target positions in the console. The Type code can be set to anything and it is sent unmodified to the lens (and the 18-55 lens just seems to apply the change whatever is going on).

**Speed Code**

Have seen value with the 15-50 PZ lens of 0x00 / 15 / 1A / 04 / 06 / FF.

I expect these these values have to be in the 'focus speed' Op100C.6004 table. It's not an index because 0xFF would be past the end - unless that just means 'fastest'.
